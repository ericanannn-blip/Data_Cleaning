# 批量上传与文件结果界面

- “选择目录”仅加入 `.dat` 文件，避免把对话 JSON 等无关文件一起上传；其他格式可使用“选择文件”。目录含 `conversation_asset_file_names.json` 时只在浏览器读取原名映射，不上传此映射。也可以单独载入映射。
- 原名映射和来源名称与服务器采用相同的安全名称规则：只取 Windows/Unix 路径的文件名部分，移除控制字符，最多保留 255 个 UTF-16 单元；空结果使用 `unnamed.dat`。
- 点击“上传 / 继续”才发送文件。在线 Worker 每次读取和发送最多一个分块，最多同时处理两个文件。队列仅绘制前 100 行，全部文件仍会处理。
- 只有服务器返回非空 ETag 的分块才视为已确认；仅有大小和哈希的待写入记录会重新发送，响应丢失时也按此规则核对。
- 暂停在当前块结束后生效。重新打开页面后重选同一批文件并载入相同映射，再点继续；页面保存上传会话 ID，不保存正文。上传前通过有界分块扫描全文件生成续传身份；同名、同大小、同时间但正文不同的文件不会共用会话。相同内容的重复队列项也按出现次序保留独立会话。重新选择的每个已确认分块都会重新计算 SHA-256，与服务器记录比较，防止同名或中间内容变化导致错误续传。
- 浏览器禁用本地存储时本次上传仍可完成，但刷新后的自动续传不可用。清除本机续传记录不会删除服务器的未完成会话或已保存原件。
- 详情提供原件下载、按检测格式命名的下载，以及包含 schema、筛选标准和证据的 JSON。文件格式分组与语义主题分类分开；未做语义判断时显示 `insufficient_evidence`。
- 大文件只检查前 64 KiB；图片/PDF/压缩包的 schema 是元数据契约，不表示已提取正文、OCR 或解压。未知 DAT 保留未知状态，不宣称解密。
- 当前 Worker 单文件上限 256 MiB；以 `/config` 为准。旧 Python 后端未声明 `resumable_uploads` 时，界面保留逐文件原始流上传。

验证：执行 `node --check backend/static/app.js` 检查语法；执行 `node scripts/test-ui.mjs` 可复现合成文件、模拟 API 的分块、续传、同名文件、暂停及大队列逻辑验证；真实浏览器交互由主任务统一验证。未把合成测试当成真实私有资料的全量验收。


## 三个独立工作区

- **文件与原件**：保留批量接入、队列、文件检索、格式过滤、原名映射和原件下载。记录标识、文件头与哈希放在详情中的高级折叠区。
- **结构 Schema**：通过 `/schemas` 读取真实分组，再以 `/files?schema=…` 查找对应文件。选择文件后调用其 `/schemas`，显示字段树、类型、必填项、规则结果及字节证据覆盖。旧记录没有指纹时明确按格式查看；二进制文件明确显示元数据契约，不暗示 OCR、解压或正文提取。完整 JSON 放在高级折叠区。
- **主题任务 Schema**：调用 `/taxonomy` 展示已有设计中的主题/任务代码、纳入/排除/边界规则和版本。文件状态单独从 `/analysis` 读取，证据不足时展示“尚未生成语义标签”，不把词表展示或格式识别当作分类完成。

工作区使用 `tablist`、`tab`、`tabpanel` 和 roving tabindex。左右箭头、Home/End 可切换并移动焦点；页面记住上次选择。公共上传 DOM 不随工作区重建，切换到 Schema 工作区时折叠为实时进度摘要，可随时展开。进行中的上传、暂停状态、队列和分块信息保持不变。

数据请求使用独立序号及当前工作区检查，旧请求不会覆盖新分组或新文件选择。各区包含加载、空内容、失败与重试说明。移动端使用单列字段区和规则卡；页面保留浅绿色视觉体系。

`node scripts/test-ui.mjs` 还会校验三面板切换、模式偏好、真实接口响应形状下的 Schema 过滤/字段树/必填与规则、实际词表数量和诚实的待复核状态、键盘焦点、过期请求拒绝，以及切换时正在上传的队列和进度不变。该测试使用模拟 API，不替代主任务的真实浏览器检查。
